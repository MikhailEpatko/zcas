# Политика безопасности

## Что не стоит публиковать

Следующие данные содержат токены, cookies, session-информацию и **не должны попадать в issues, PR или любой публичный контекст**:

- `credentials.json`, `config.json` (из `~/.zcode/v2/` или любые копии)
- `accounts/` — снимки аккаунтов с OAuth-токенами
- `.last/` — бэкапы логина
- `browser_profile/` — cookie и session браузера OAuth
- `.env`, `.env.local` — переменные окружения с секретами
- `.har`-файлы — содержат полные HTTP-запросы с заголовками авторизации

## Принципы проекта

- Все данные хранятся **локально** — проект не отправляет ничего на внешние серверы
- Передача логина между аккаунтами — это локальная замена файлов, без сетевого взаимодействия
- AES-256-GCM шифрование `enc:v1:` / `enc:v2:` вводит сам ZCode; инструмент расшифровывает значения логина, чтобы определить аккаунт, и шифрует новые при добавлении через CLI OAuth
- Ключ `enc:v2:os` инструмент читает из системного хранилища секретов (на macOS — Keychain, запись «ZCode Credential Encryption») утилитой `security`; ключ держится только в памяти процесса и никуда не записывается. Доступ к записи Keychain разрешает пользователь вручную
