# ZCode Account Switcher

> Инструмент для быстрого переключения аккаунтов ZCode — сохраняет снимки логина и позволяет переключаться между аккаунтами **без повторного входа через OAuth и код подтверждения**.

Проект вдохновлён: https://github.com/arbiswork-boop/zcode-switcher-account

---

## Возможности

- **Совместимость** - совместим с новой версией ZCode v.4.x
- **CLI (`zcas`)** — лёгкая командная строка, нулевые зависимости, удобно для скриптов
- **Атомарное переключение** — бэкап → замена файлов логина → перезапуск, с возможностью отката
- **Дедупликация** — повторный снимок того же аккаунта не создаёт дубль
- **Кроссплатформенность** - легко доработать под любую OS

## Использование

### CLI

```sh
zcas status                                    # текущий аккаунт + список
zcas list                                      # все сохранённые аккаунты
# zcas quota                                     # квота: всего / использовано / остаток / по моделям (in progress)
zcas capture --name "Основной"                 # сохранить текущий логин как снимок
zcas use 2                                      # переключиться на аккаунт №2
zcas use a869                                   # по id или префиксу id
zcas rename 2 "Новое имя"                       # переименовать
zcas delete 2                                   # удалить снимок
zcas rollback                                   # откат к логину до последнего переключения
zcas kill                                       # закрыть ZCode
zcas launch                                     # запустить ZCode
```

`<id|номер>` — порядковый номер из списка, короткий id или префикс id (напр. `a869` → `a869314f`).


### Рабочий процесс

1. Войдите в ZCode первым аккаунтом → `zcas capture --name "..."`.
2. Выйдите из ZCode → войдите вторым аккаунтом → снова `capture`.
3. Повторите для всех аккаунтов.
4. Переключайтесь: `zcas status` → `zcas use N`. При ошибке — `zcas rollback`.

## Как это работает

Логин ZCode хранится в `~/.zcode/v2/` (пути — см. `src/paths.js`):

| Файл | Содержимое |
|------|------------|
| `credentials.json` | OAuth-токены, JWT для вызова API и профиль пользователя; значения зашифрованы (`enc:v1:` / `enc:v2:`, AES-256-GCM) |
| `config.json` | `apiKey` (JWT в base64, payload содержит `user_id`) для каждого провайдера — только у старых версий клиента; в 4.x файл не создаётся |

Это **один полный логин**. Инструмент делает:

1. **capture** — сохраняет файлы логина как снимок аккаунта (`config.json` — только если он есть)
2. **use** — закрывает ZCode → бэкапит текущий логин в `.last/` → атомарно заменяет файлы → перезапускает
3. Отпечаток аккаунта извлекается из `user_id` JWT клиента (для дедупликации и именования): у клиента 4.x JWT (`zcodejwttoken`) лежит зашифрованным в `credentials.json`, у старого — открытым в `config.json`

### Шифрование и Keychain (macOS)

Клиент 4.x шифрует значения в формате `enc:v2:os:` случайным ключом из системного хранилища секретов (на macOS — Keychain, запись «ZCode Credential Encryption»). Чтобы определить аккаунт, инструмент читает этот ключ оттуда же утилитой `security`:

- при первом запуске macOS спросит разрешение на доступ к записи — выберите **«Всегда разрешать»**; без ответа команда через минуту завершится ошибкой;
- ключ привязан к машине: снимок с `enc:v2:os` с другого компьютера (или другой учётной записи) на этой машине не расшифруется.

## Хранение данных

Все данные хранятся **локально**, внутри репозитория:

```
accounts/              # снимки аккаунтов (autogenerated, не коммитить)
.last/                 # бэкап перед последним переключением
browser_profile/       # OAuth-браузерная сессия
```

Не коммитьте эти директории — они содержат токены, cookies и session-данные.

## Безопасность

- **Переключение требует закрытого ZCode** — работающий клиент перезапишет файлы логина. `use` по умолчанию сам завершает и перезапускает.
- **Автобэкап** — перед каждым `use` текущие файлы копируются в `.last/`, доступен `rollback`.
- **Атомарная запись** — сначала `.tmp`, затем `rename` — нет «наполовину записанных» файлов.
- **Самовосстановление** — при ошибке замены состояние восстанавливается из `.last`.

> ⚠️ **Не запускайте `zcas use` / `kill` / `rollback` из встроенного терминала ZCode** — это завершит процесс ZCode и ваш терминал. Используйте внешний терминал ОС.

---

### Токены протухают

`access_token` имеет срок действия. ZCode автоматически продлевает через refresh при запуске. Если аккаунт долго не использовался — войдите заново и сделайте `capture --overwrite`.
